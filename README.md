# Honkai-style real-time rendering

简称 **Honkai Render**。面向 Windows 的开源角色动捕与卡通渲染应用：导入自己的 MMD 角色，通过摄像头驱动面部、手势和上肢，再通过 Spout2 向 OBS 输出高清透明视频。渲染以米哈游游戏的卡通视觉风格为参考，采用自有着色器。

**程序、源码和 Release 均不带角色模型或贴图，首次启动为空场景。** 本项目不是游戏原版渲染器，也不附带游戏资源。

## 使用

从 Releases 下载 Windows x64 ZIP，完整解压后运行 `HonkaiRender.exe`。运行不需要 Python、Blender 或开发工具，不会在启动时打开摄像头。

1. 通过“模型”导入 ZIP / 7z，选择包内 PMX，也可拖入压缩包。贴图应包含在原始包中。
2. 在“捕捉”选择摄像头和动捕模式，点击开始；可打开同一采集帧的视频及关键点预览。
3. 在“映射”调整眼睛阈值、范围、平滑和 Sigmoid 曲率。曲线实时圆点显示当前识别值。
4. 在“画面”调整描边、相机、MSAA 和 OBS 输出；在“场景”设置灯光、阴影、背景、图片或 GLB 场景。

默认仅角色展示区域透明，保留系统标题栏；浅色菜单保持不透明、支持缩放、拖动和收起。常驻面板只保留六个入口及捕捉状态。不包含游戏行走控制或战斗。

默认 **VTuber** 模式驱动上半身、头部、表情、手臂与手指，下肢保持站姿。**全身动捕** 额外驱动骨盆、双腿和脚朝向，支持下蹲、抬腿与转身。全身站直后可点击“重置站姿”；双髋、双膝及脚需要进入画面。每侧丢失后短暂保持，再平滑回到中立姿态，重获后平滑接回。

“捕捉 → 姿态模型”默认使用 MediaPipe Pose Landmarker **Full**，保留 **Lite** 供性能较弱的电脑选择。修改后点击“应用捕捉设置”生效；捕捉正在运行时会停止旧会话并用新模型重新开始。两种模型均随包提供，正常使用无需联网；面部、手部模型不变。诊断 JSON 记录实际加载的姿态模型。

全身模式按实际蒙皮权重选择 D 变形腿链或标准腿链，使用模型骨长、鞋底偏移及脚锚点约束，减少站立滑步。根部位置由单目支持脚估计：水平位移限制在 35 厘米，垂直为 -45～20 厘米，不提供真实全局行走轨迹，也不能消除遮挡产生的歧义。切回 VTuber 会恢复中立根位置与下肢。

“捕捉 → 手势辅助”默认关闭。开启后，连续检测接近握拳、张开或伸食指时，手指平滑收敛到模型适配的预制姿态；未识别或遮挡时保留实时结果，手腕方向仍由动捕驱动。辅助不会修正识别器的肩肘腕深度估计。

手臂／手掌短暂丢失时保持最后有效目标 150 毫秒，再平滑释放到中立；关闭对应映射或重新居中会清除保持。模型缺少一侧单眼形态键时，使用可用的双眼同步眨眼，避免叠加闭合。

动捕通过原生 C++ MediaPipe 在 CPU 上推理，GPU 负责角色渲染和视频输出。界面中的 Hz 是动捕更新率，FPS 是渲染帧率，两者独立。

摄像头放在用户左前或右前时，在“捕捉 → 相机方位校正”启用校正。俯视图拖动左右和前后位置，侧视图调整相对胸口的高差；左右按用户本人定义。默认朝向胸口，偏航、俯仰和画面倾斜可数值微调。参数按摄像头编号保存，换设备或系统重新排列编号后需要检查。校正默认关闭，先转换身体、手臂、手与头部方向，再映射骨骼；表情、眨眼、原始预览和角色展示镜头保持独立。手动方位校正不能恢复被遮挡或出画面的关节。

## 导入与渲染

角色 PMX 直接在应用内由 C++ 读取。独立的 [MMD 加载与渲染器仓库](https://github.com/furinasdog/Honkai-MMD-Loader)通过 Git submodule 固定版本。读取原始 UV、材质面范围、贴图、骨骼、顶点表情、描边权重和刚体关节；重复使用的贴图共享内存。缺失必需贴图、损坏数据或超出支持范围时取消导入，并保留当前角色。

渲染包括分材质明暗分层、头部空间面部阴影、头发高光和 MMD 几何描边。遵守材质的单面／双面设置，避免背面内衬覆盖外层贴图。面部开口抑制内轮廓外壳，保留脸部外轮廓、原始嘴唇贴图和鼻部几何。材质识别兼容简繁中文、日文和常见英文名称，未知模型仍可能需要适配。

“模型 → 增强表现”默认开启：身体和衣物使用宽阔的二分明暗，面部独立处理，避免普通投射阴影把身体切成零碎暗块。缺图时根据当前网格及 UV 生成面部 SDF 风格阈值、鼻部辅助线和头发高光遮罩，并按几何指纹缓存。这是几何近似，不是官方手绘 FaceMap，不能保证所有脸型与游戏实机完全一致；关闭后不使用这些辅助图，回到原始贴图及基础卡通着色。原始 PMX、贴图及顶点表情不会被改写。

“模型 → 刘海眼透”默认关闭，支持强度调节。开启后通过可见头发的模板遮罩混回眉眼；前方的手、衣物或场景物体继续遮挡眼睛，背向镜头时关闭混回。眼白和口腔材质不参与眼透。

“模型 → 增强贴图…”按具体材质导入 FaceMap（R 区域、G 遮蔽、B 鼻线、A 面部 SDF）、独立灰度 SDF、LightMap（R 遮蔽、G 明暗阈值、B 高光、A 材质分区）、冷暖 Ramp 或灰度高光遮罩。图片需要与该材质的 UV 匹配；Ramp 按身体 8 行、头发 1 行采样。手动图优先于自动图。支持 PNG/TGA/JPEG/BMP/WebP，文件上限 64 MB、尺寸上限 8192×8192。图片复制到用户缓存并按模型保存，移动原文件不影响使用；“移除”恢复自动辅助图或基础方案。关闭增强表现也会停用手动增强贴图。算法和参考资料见 [渲染说明](docs/rendering.md)。

“场景 → 计算阴影”可关闭。关闭后所有材质使用完整源贴图颜色，跳过法线、投影及面部阴影计算，保留贴图本身的色块、透明度与描边；设置会保存并应用到后续导入的模型。

PMX 刚体和弹簧 6DOF 关节映射到 Jolt，以 120 Hz 求解；头发防穿模辅助覆盖头颈、肩膀和身体。碰撞使用模型代理形状，不是布料网格自碰撞，因此不能保证所有姿势完全无穿插。

当前已知问题：符华“鹤鸣太虚”的侧发在部分转头姿态仍与袖子相交，碰撞代理未覆盖完整袖面。本轮改进了物理父链同步和动态衣发关节约束，未解决这项模型适配问题。

胡桃模型的大袖仅随手臂蒙皮，没有独立动态袖链，手指也没有对应刚体；其袖／手碰撞属于作者模型配置限制。

支持 BDEF1/2/4，SDEF/QDEF 使用线性蒙皮兼容模式；顶点和顶点组合表情可用于动捕。骨骼／UV／材质／冲量变形、附加变换约束和 PMX 软体尚未完整支持。详见加载器的 UPSTREAM.md。

## OBS 输出

安装 [OBS Spout2 插件](https://github.com/Off-World-Live/obs-spout2-plugin)，在“画面 → OBS 视频输出”选择 720p、1080p、1440p（2K）或 4K，30 / 60 FPS，启动后在 OBS 选择 `BengRender` 源。Alpha 使用预乘。输出独立于窗口尺寸，只包含角色，不包含菜单或附加场景。最小化窗口可继续输出。

当前提供 Spout2 视频源，不注册 Windows 系统摄像头。会议软件可通过 OBS 的普通虚拟摄像头转发，普通视频链路不保留 Alpha。4K 60 FPS 取决于显卡和模型负载。独立原生 Spout 接收端已验证，OBS 插件内端到端接收尚未实测。

## 从源码构建

需要 Windows SDK、C++17、CMake 3.20+、PowerShell 7，以及 Godot 4.7 单精度 x64 编辑器和匹配的导出模板。已验证 Visual Studio 2026；其他编译器尚未验证。没有 Python 绑定生成步骤，不定制 Godot 引擎。

```powershell
git clone --recurse-submodules https://github.com/furinasdog/Honkai-Style-RealTime-Rendering.git
cd Honkai-Style-RealTime-Rendering
./tools/fetch_dependencies.ps1
# $Godot 指向本机 Godot 4.7 编辑器
cmake -S native -B build/native -G "Visual Studio 18 2026" -A x64 "-DGODOT_EXECUTABLE=$Godot" -DBUILD_NATIVE_TESTS=ON
cmake --build build/native --config Release --parallel
ctest --test-dir build/native -C Release --output-on-failure
./tools/build_portable.ps1 -ExportOnly -GodotExecutable $Godot
```

依赖准备脚本从固定版本官方发行文件提取 MediaPipe 原生 DLL、7z DLL 和 Tasks 模型，并核对 SHA-256。MediaPipe 的发行压缩包是 wheel，但只提取原生 DLL，不安装或运行 Python。头文件、第三方许可和版本清单随源码保留。首次准备依赖需要联网，正常运行无需联网。

便携包仅包含原生运行所需组件，详见 [PORTABLE_BUILD.md](PORTABLE_BUILD.md)。`tools/import_pmx_blender.py` 保留为受控开发参考脚本，不由应用调用，也不进入导出副本或发行包。

## 验证与许可

离线识别回放需要 MediaPipe 官方测试图，开发者可执行 `./tools/fetch_dependencies.ps1 -TestFixtures` 下载并校验固定样本，再用 Godot 运行 `tests/test_native_capture_replay.gd`。这些测试图不进入发行包，普通依赖准备也不会下载它们。测试时请使用独立的 `APPDATA` 目录，以免修改日常设置。

`tests/test_native_importer.gd` 验证 ZIP 到原生 PMX 的完整路径；`test_imported_model.gd` 验证完整面数、映射、物理和多姿态渲染；`test_toon_materials.gd` 用合成几何验证反面材质不会覆盖正面。其余测试覆盖动捕越界、阈值曲率、设置、透明窗口及 Spout 输出。真实角色测试由使用者提供私有资源，不随仓库发布。普通回归不打开摄像头，`test_camera_live.gd` 是需手动运行的硬件检查。

`test_capture_calibration.gd` 覆盖斜置摄像头数据到头部、双臂和手指的完整映射及双视图设置；`test_toon_palette.gd` 验证线性色板与合并后的一次二分。`test_hair_mesh_contact.gd` 使用修改器完成后的 GPU 蒙皮顶点，检查采样发片与身体三角的相交和实体内点；有限姿态通过不能证明任意动作都不穿模。

`test_fullbody_retarget.gd` 覆盖接地、下蹲、抬腿、脚向、躯干转身、单侧／整帧丢失重获和相机校正；`test_fullbody_native_rig.gd` 验证私有 PMX 的真实蒙皮顶点随腿部运动、支持脚与鞋底基准。脚底矩形代理和普通单目摄像头仍有精度限制。

抬臂等姿态发生偏差时，可在捕捉问题出现的当下点击“应用 → 保存姿态诊断”。应用导出单帧 JSON 并打开文件夹，包含身体／手部关键点、校正及镜头、肩肘腕映射参数，不包含 RGB、人脸点、模型或绝对模型路径，也不会自动上传。静态预览截图无法证明三维深度估计正确，相关识别偏差仍需诊断数据定位。

一次用户诊断重放确认，小臂前探已存在于 Lite 的原始 world landmarks，骨骼映射跟随该方向。Full 在同图离线对照中减少了前向分量，但该截图带有叠加标记且缺少真实三维标注，不能据此承诺实摄动作完全正确。Full、Lite 都是单目三维估计，仍可能产生遮挡和深度歧义。
